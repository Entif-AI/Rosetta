# Pack manifest validation

`validate-packs.mjs` is the current local Pack-root conformance checker. It first validates each discovered `packs/*/pack.json` against the repository's [`pack-manifest.schema.json`](../../packs/_schemas/pack-manifest.schema.json). An invalid or unreadable manifest produces a typed `manifest-schema-invalid` or `manifest-json-invalid` error before the checker computes its Pack ID, reads declared paths/Profiles, or claims dependency-graph validity. Valid manifests then receive the existing `rosetta-pack-id-v1` integrity, declared asset/Profile and local DocID/dependency checks.

The JSON Schema defines the machine-recognized keys. `$schema` is an allowed local metadata field. `compatible_core` and `depends_on` remain required per [ROCK-3111-C](../../docs/RFCs/ROCK-3111-C-RRP-Pack-Filesystem-Contract-v0.2.0.md). RFC examples must conform to this executable manifest shape and do not implicitly expand it. Invalid manifests must be corrected or migrated explicitly.

For existing `entrypoints.schema[]` files, the validator also parses the declared JSON and checks JSON Schema Draft 2020-12 meta-schema validity. A missing declared path retains `declared-path-missing` without a duplicate schema error. Malformed JSON receives `schema-json-invalid`; a meta-schema-invalid document receives `schema-invalid`; a declared dialect other than the supported 2020-12 dialect receives `schema-dialect-unsupported`, which does **not** assert that the other standard is invalid. Ajv's non-standard strict lint checks are deliberately disabled. This stage does not execute schemas against instances, resolve external references, validate SHACL graphs or verify Pack-specific test vectors.

Declared entrypoint, export, Profile and schema paths must remain inside the Pack root and resolve through regular directories to a regular file. Absolute paths, any `..` traversal, and any symbolic-link component fail before the validator reads the declared asset. The supplied Pack root and workspace Packs root must themselves be direct directories rather than symbolic links, and workspace discovery rejects a non-internal symbolic-link child as `pack-root-unsafe`; ancestor path aliases remain allowed. This keeps declared Pack assets inside the byte set bound by `rosetta-pack-id-v1`; the Pack-ID algorithm itself is unchanged. Repeated declarations of one safe missing asset collapse by normalized path identity to one missing-path error, while a Profile-only missing asset retains `profile-path-missing`.

Run `pnpm exec nx run pack-conformance:test` for the focused negative vectors and `pnpm run packs:conformance` for current workspace roots. The conformance command verifies declared Pack structure and identity. It does **not** by itself provide a complete release decision, execute every Pack example and test vector, prove cryptographic signatures, admit an installation, or authorize a registry/promotion change.

The composed Pack release gate, bootstrap workspace proof, deterministic release report, CI integration, and any later admission/write workflow remain owned by [#790](https://github.com/Entif-AI/Rosetta/issues/790) and its downstream accepted work. This first step has no new Core semantics or Pack-ID algorithm.
