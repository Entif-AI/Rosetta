Resolve governing product/semantic authority and the public/private boundary before
changing behavior. Rosetta owns meaning; Spec Kit composes workflow; Nx runs gates.
Generated files are execution veneers and evidence, never normative authority.

Choose one next capability from the user's intent and current evidence:

- Existing behavior without sufficient documentation: baseline.
- New bounded requirement: specify; then clarify when needed.
- Accepted requirement ready for design: plan.
- Accepted plan ready for execution: tasks; implement after admission.
- Cross-artifact assessment: analyze.
- Convergence evidence: convergence; verified merge evidence: verify.
- Stable task-to-work binding: issue-sync (preview; external writes need authorization).
- Admission: admit.

Load only the selected capability by running from the workspace root:
`python node_modules/@entif-ai/nx-governance/spec-kit/install.py --route <capability>`.
Read and follow that selected command's instructions. Resolve hook invocations through
the same route when reached. Do not enumerate or preload the runtime command directory.
Keep original task IDs, source finding lineage and durable issue owners. Never create
branches, replace source authority with observed code, bypass failed gates, or blindly
retry an ambiguous external write. Regeneration requires source changes plus explicit
refresh; local modifications require review before overwrite.
