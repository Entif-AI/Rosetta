# Envelope family crosswalk

**Status:** Proposed cross-family semantic/conformance clarification for [#1799](https://github.com/Entif-AI/Rosetta/issues/1799), version 0.1. **Owner:** `@entif-ai/rosetta-schemas` for catalog, boundary validation and fixtures; `docs/governance/genesis/SEMANTIC_AUDIT.md` for the semantic audit. The [v3 Core Terminology Lock](../../../docs/RFCs/Rosetta%20v3.0.0%20Core%20Spine%20Specification.md) and the existing [AuthZ #630](https://github.com/Entif-AI/Rosetta/issues/630) and [Messaging #220](https://github.com/Entif-AI/Rosetta/issues/220) contracts continue to govern their respective meaning.

**Envelope** is an ordinary structural/composition word. It is not a free-standing `rosetta.envelope` kind, a generic entitlement, or a universal superclass. A named envelope identifies the boundary that owns its payload and metadata. A wrapper's signature, expiry, CID or routing acceptance proves only the property its actual validator and authority establish.

## Composition and compatibility

A transport `INCIDENT_ENVELOPE` remains under its existing message schema and wire ID. To discuss a Core sealed Incident, construct a distinct `rosetta.incident` Tile and prove its required properties through the Core owner. If transport must carry it, use an explicitly versioned reference/mapping governed by #220 and the Core Incident owner; preserve the original report as its own evidence. **There is currently no implicit conversion or interchangeable alias.**

The existing wire `INCIDENT_ENVELOPE` name is retained. Do not rename it to `rosetta.incident`, drop its `msg_type`, or reinterpret `incidentId` as a canonical CID. A future breaking rename needs a reviewed migration table, a new schema version, dual-read behavior where warranted, and fixtures preserving old messages. Repository searches for bare `AuthEnvelope`, `IncidentEnvelope`, `TaskEnvelope` and a bare `Envelope` should resolve each occurrence to its actual owner, rather than adding new aliases.

Authority expiration, revocation/invalidity, supersession, policy/source frontier, transport TTL, session/AuthN lifetime, cache freshness and storage retention are orthogonal. The current v1 Authority Envelope schema requires `validity.expiresAt`; whether a standing non-expiring variant is needed is a **separately versioned AuthZ decision under #630/#1746**, not a change introduced by this crosswalk. No session identity, role or group is universally required to source rights; policy may require authenticated actor evidence for selected operations.

New envelope-shaped contracts use an owning issue, namespaced versioned identity, Core-descent classification, catalog/source references and an independently useful positive/negative test. `getCoreDescent` deliberately has no registration for `rosetta.envelope`. `validateSchemaCatalogCoverage` catches missing source/validator/documentation declarations for supported IDs. Nx task/project edges do not grant semantic substitutability across these families.

## Conformance evidence and limitations

`packages/rosetta-schemas/src/lib/envelope-families.spec.ts` runs a real report through the Agentic Messaging validator and inert data-plane policy, rejects its promotion to `rosetta.incident`, accepts a bounded Core Incident payload shape, refuses invalid quorum/blob references, and confirms AuthZ/transport/Core catalog separation. `packages/rosetta-schemas/src/lib/authority-envelope.spec.ts` tests structural attenuation. `packages/rosetta-guard/src/lib/authority-state.spec.ts` and the integrated Guard/API proof cover revocation and current-state enforcement separately. The latter remains a bounded **local reference** path, without a production provider claim.

The Core constructor refuses empty or duplicate seal participants, a quorum outside the declared participants, and an empty encrypted blob reference. The constructor and structural validator **do not** encrypt incident content, prove a stored ciphertext's existence, perform quorum release, or establish protected incident visibility. The test for the Core Incident family therefore reports **shape/integrity proof**, with sealed access and cryptographic quorum behavior **not yet implemented/proven**. Source inspection also provides no basis to infer Mailroom transport custody from schema registration alone.

This crosswalk records existing authority and makes its boundary testable. It does not amend the Core Terminology Lock, grant permission, introduce a new Core Tile kind, replace AuthZ state, or change any existing message wire identifier.
