# trace-kin-v1

Public observable analytics Profile owned by #1669 and independently re-proven on active FalkorDB 6.0.1 by #1736. Pure measurement consumes validated trace.normalization.v1; direct Cypher independently proves structural counts. Historical Neo4j results remain the differential reference. Result identity binds source fixture/digest, normalization Profile/version/digest, declared metric Profile/version and the full series. parseTraceKinematics checks schema, digest, predecessors, count consistency and classification criteria. No Core kind is added.

Every row names its snapshot/predecessor, run/window and physical source sequence. SourceBytes and recordCount are cumulative physical source-prefix sizes/counts from normalization; normalizedBytes is reconstructed canonical object-state size, before dictionary substitution. ObjectCount and uniqueObjectIds describe current membership. DuplicatePayloads counts exact equal canonical content values beyond the first occurrence in that snapshot, including small inline content. The five delta counts retain normalization's explicit dispositions. Survivors are predecessor/current intersections; disappeared IDs are removals. Reappearance requires earlier presence in the same run/window, absence from that run's declared predecessor and current presence. A return to an earlier run uses that run's predecessor, never assumes a reset erased it.

Keys are canonical [objectId, top-level stableFields key] tuples. Signatures are explicit request IDs, tool-object IDs and finished tool [requestId,objectId] tuples. They are observable identity recurrence, not proof of duplicate executions. Current signature/key sets expose survival, disappearance and run/window-scoped reappearance. RepeatedRequests, repeatedTools and repeatedResults count occurrences beyond the first within the source prefix for the current run/window. UnchangedResults further requires exactly equal canonical content for the same result identifier. Equality is structural, without model inference.

ObjectShrinkRatio = max(0, 1 - currentObjectCount/max(1, previousObjectCount)). ByteShrinkRatio uses corresponding normalized bytes. Both are zero without a predecessor. Representation_shrink requires advancing source sequence, lower object count, lower normalized byte count and removals. Compaction_candidate additionally requires survivors, no explicit reset and the same run/window. No arbitrary percentage threshold is applied.

These are client-visible representation dynamics. They establish nothing about provider/model internal memory compaction, forgetting, deletion, summarization, recall or causality. This caveat is required in serialized output. No salience/routing/scoring policy is implemented.

The independently declared generated S0-S5 literal series in projection-adapters/test-vectors/trace/generated-kinematics.expected.json proves S2 decreases from five objects/1200 bytes to three/760 with A,C,E surviving and B,D disappearing: object shrink 0.4, byte shrink 0.3666666666666667, candidate true. S4 is an explicit new-run reset with no survivors and candidate false. S5 shows B reappearing in the original branch. These findings are deliberately generated fixture behavior, not claims that the captured stream exhibited compaction. The captured fixture separately proves repeated explicit request IDs and 66 observable client materializations.

Direct morphology.cypher checks source/state sizes, counts and all five dispositions against both report series. Neighborhood.cypher exports the immediate pre/post snapshots and object states for a declared transition. tools/trace-graph/evidence/falkordb-kinematics-proof.json binds active independent query/metric parity; neo4j-proof.json remains immutable historical evidence. Report JSON files retain complete deterministic measurements. No LLM is needed.
