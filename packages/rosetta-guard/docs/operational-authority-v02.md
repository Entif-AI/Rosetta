# Operational authority reference

`LocalAuthorityState` (#1758, under #630/#1757) is a trusted local state owner, not an agent-facing grant interface. `authorizeCurrentOperation` resolves current state at the handler boundary and feeds the existing #1747 evaluator. Consumers supply intent, trusted capability ceilings and independent gates; they do not construct `CurrentAuthoritySource` objects.

The reference persists immutable, content-addressed `rosetta.observation` records with typed authority-event fields. Roots, delegated facts, invalidity and current policy bindings remain distinct. Each append creates an exclusively opened revision file, fsyncs its contents and containing directory, and reads the exact bytes back. A revision conflict refuses a concurrent write. Incomplete/corrupt history fails closed; ambiguous acknowledgements require reconciliation by mutation identity. The current index is derived from history, never written over prior facts.

Resolution accepts one authority leaf and closes its parent/source chain. It binds every current projection to the same content frontier and monotonic revision, checks subject/validity/current policy, refuses implicit union and amplification, and resolves policy-required actor evidence through a trusted binder. Missing, ambiguous, stale or invalid inputs have explicit refusal codes. The returned objects are detached from stored history. `inspect(revision)` provides historical evidence; enforcement cannot select an old revision as current state.

An operation may require a minimum acknowledged revision. After revocation at R, a causally later operation requiring R or later resolves at least that revision or refuses; an old envelope cannot bypass current invalidity. This is a bounded local reference, not a claim of globally linearizable distributed authorization. Raw append mechanics are NOT_AGENT_FACING. #1761 owns governed mutation above them; #1759 owns authenticated actor binding; #1760 owns credential mediation; #994 retains independent admission ownership.

The seven focused state tests cover restart/readback, source closure, attenuation, implicit composition refusal, revision/invalidity, historical inspection, current policy drift, conflicting writers, duplicate source identity, corrupt history, detached projections, unrelated roots, and handler-time rejection of an old envelope. No Core kind or role-based rights ontology is added.
# Authenticated actor binding (#1759)

`SignedActorEvidenceRegistry` consumes the existing `rosetta-receipts` Ed25519 verifier. A trusted owner pins an issuer, key ID, public key, trust-anchor ref, and runtime session/workload/source frontier. A signed Receipt binds exactly one typed workload assertion Observation. A valid signature from an unpinned key is refused. Normalized evidence carries subject, issuer, authentication method, validity, runtime binding and source refs; it carries no credential or private key.

The reference registry is an in-process authenticated source. Its current revision/frontier and explicit evidence/issuer invalidity are consulted on each resolution; it does not promise persistent or distributed authentication-state reconciliation. Production integration must connect the actual identity owner's live validity source. #703 owns workload transport identity, #1077 remote ingress authentication, #96 signer admission, and #1296 extra identity-sensitive constraints. This bridge does not absorb those owners.

Authentication establishes evidence only. Neither binding an assertion nor replaying its signed Receipt creates an authority fact. A required evidence ref must resolve for the authority subject and the configured session/workload, be current at the configured source frontier, and be unexpired/unrevoked. Resolution supplies verified refs to #1747 only after these checks. Raw binding and revocation mechanics are NOT_AGENT_FACING.
