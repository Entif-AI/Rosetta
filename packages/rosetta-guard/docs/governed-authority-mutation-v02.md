# Governed local authority mutation (#1761)

`ConfiguredRootAuthoritySource` consumes an independently installed operator configuration: admitted authority powers, domain, subject, policy, validity and delegation ceiling. A pinned Ed25519 signed Receipt authenticates an exactly matching configuration witness. The configuration is the authority source; neither a signature, signer identity, Observation nor Receipt independently grants powers. A model/task request cannot install this source. Its real local current-state resolver reuses #1758. Source installation/restart reconciles immutable source records and preserves later source invalidity.

`GovernedAuthorityMutator` operates on a separate target authority journal. Policy establishment and standing-root grants require the installed operator source. A root grant must attenuate its scope, validity, context and delegation ceiling. Delegation requires a current parent with the explicit `authority.delegate` power. Revocation, invalidation and supersession require independently resolved current authority with the corresponding operation. Expiry remains part of declared validity and is checked at current resolution.

Every target change goes through #994/#1765: normalize; evaluate current authority and independent workflow/startup narrowing; ground source and target frontiers; persist checkpoint; recheck; append using the captured target revision; read back; persist canonical Receipt closure; queue a real durable projection-job record. The source revision and target append revision are separately fenced, including during initial establishment. This reference uses the existing `local-write` effect class; it introduces no Core kind or rights ontology.

Event identities are deterministic. An identical structural payload returns reconciled historical evidence without another append, even if JSON object-key order changes. A different payload under the same identity is refused. Replaying a pre-revoke grant acknowledgement does not change current state or revive authority. The returned revision/frontier describe current target state, including later invalidity; the old Receipt remains historical evidence.

After lost acknowledgement or Receipt storage failure, reconciliation requires the persisted checkpoint, matching Action, actual target readback and completed successful check. It reconstructs only missing evidence closure and acknowledgement, never repeats apply. Missing or ambiguous closure remains held. Invalidity records retain history; unrelated independently rooted grants remain resolvable.

Raw source installation, storage previews and mutation mechanics are NOT_AGENT_FACING. The bounded reference assumes a trusted local operator installation and one serialized target append winner; it does not replace production root/signer admission, identity-source lifecycle or distributed transactions.
